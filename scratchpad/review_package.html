a봉인 원자성 + SHA-256

1

봉인 원자성. snapshot이 job 행을 FOR UPDATE로 잠근 뒤 GJM을 확정하고 같은 트랜잭션에서 material_snapshot_at을 기록. seal 트리거를 status뿐 아니라 봉인 시각에도 연결 — 봉인 후에는 pending이라도 GJM 변경을 거부. 재봉인은 멱등 no-op.

SELECT … FOR UPDATE (job)
→ INSERT GJM (pending)
→ count + SHA-256 manifest + material_snapshot_at (봉인)
seal 트리거: material_snapshot_at IS NOT NULL → 변경 거부
2

manifest SHA-256. md5→sha256로 통일. {ordinal, material_version_id, byte_size, content_sha256}를 정렬·UTF-8·무공백 canonical로 직렬화해 해시.

aworker_token 실행권

3

claim_job이 CAS로 worker_token·claimed_at을 기록하고, 이후 상태전이는 토큰이 일치할 때만 허용. stale 워커가 뒤늦게 다른 워커의 job을 완료 처리하는 것을 차단합니다.

d병원당 실행 중 job 1개

4

부분 유니크 인덱스(generating/generated/ingesting)로 같은 병원 동시 실행을 1개로 강제(병원 간 병렬은 허용). 위반은 hospital_busy로 안내. 인덱스 생성 전 기존 중복 active는 병원별 최신 1개만 남기고 stale 정리.

5

작업 격리. 병원당 active 1개 + 생성 전 raw/ 정리로 동시 오염을 방지. 완전한 job별 디렉터리 격리는 병원 내 병렬 실행을 여는 시점(heartbeat·queue와 함께)에 적용.
