3evidence service (assess_claim)

명시

version_id·script_id를 명시적으로 받음(암묵적 current 조회 금지).

current

mutation 시 scripts FOR UPDATE + current_version==target 재검사 → 편집으로 current가 바뀐 뒤 과거 화면 저장은 VersionConflict.

동결

approved/revoked version 근거 변경 금지(InvalidStateTransition). claim이 그 version 소속인지 검증(NotFound).

잠금

approval과 동일 순서(scripts→approval state→claim). 권한 approver/admin. 단일 claim 처리(부분성공 없음).

▤DB 백스톱 + /studio 교체

trigger

fn_freeze_assessment_if_decided — approved/revoked version의 claim_assessments INSERT를 2BP01로 차단(service 우회 방지). rls_sql의 lock 트리거는 유지.

route

/studio ui_review를 evidence service 호출로 교체(폼에 version_id/script_id hidden). 라우트=파싱+예외매핑만.

①Step 4 사전정리 — SQLSTATE (완료)

done

지적대로 2BP01(PG 내장 dependent_objects_still_exist) 재사용을 제거하고 도메인 코드로 분리 — P2013=decided_version_frozen(승인/철회 version 내용·근거 동결), P2014=supersede 충돌. rls_sql content freeze + assessment freeze/superseded 함수 전부 교체, 매핑·테스트 갱신, 라이브 함수 재적용.

②Step 4 사전정리 — waived 모델 (계획, 착수 전)

축분리

verification_status(pending/verified/failed)와 human_decision(accepted/rejected/waived/not_applicable)을 분리. claim_assessments에 human_decision 컬럼+CHECK 추가 방향.

최신

승인 gate는 claim별 최신 유효 human assessment만 사용(created_at DESC,id DESC 또는 review_seq로 결정적). waived는 사유·capability·audit 필수.

▲Step 4 approval service — 계획

core

정상 fn_approve_version CREATE OR REPLACE 강화(scripts FOR UPDATE·current==target·귀속·상태전이·최신 evidence prereq·작성자≠승인자·audit).

self

자기승인은 별도 fn_self_approve_version(creator==actor + allow_self_approval + admin self_override + 사유).

상태

fn_reject_version/fn_revoke_version(전이표; revoke는 비-current도 허용) + publish/export gate(current&approved만).
