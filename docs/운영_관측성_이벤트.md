# 운영 관측성 — 구조화 이벤트 카탈로그

`services/observability.py`가 이벤트를 **stdout에 JSON 한 줄**로 방출한다. Render 로그 스트림이 수집하므로 별도 집계 시스템 없이 로그 필터/집계로 확인한다. 모든 이벤트에 `obs`(범주)·`ts`. 관측 실패는 요청을 깨지 않는다(예외 안전, `OBS_DISABLE=1`로 끔).

## HTTP (`obs=http`, app=studio)
`/studio` 매 요청. redirect 은퇴 판단의 핵심.

| 필드 | 의미 |
|---|---|
| `method` | GET=redirect 가능 / POST·API=compat wrapper 필요 |
| `rule` | route 패턴(예 `/ui/<slug>/versions/<version_id>`) — 집계 단위 |
| `endpoint` | Flask endpoint 이름 |
| `status` | 404↑=누락 deep link, 401/403↑=세션·ActorContext 전환 문제, 5xx↑=새 route 회귀 |
| `redirect` / `redirect_target` | 3xx 여부와 목적지(**UUID `<id>`로 마스킹**, 쿼리 제거) |
| `latency_ms` / `request_id` | 지연 / 요청 상관 |

## 예외 (`obs=service_error`, `obs=sqlstate`)
- `service_error`: 모든 ServiceError 생성 단일 병목. `code`·`status`·`type`·`msg`(200자).
- `sqlstate`: DB SQLSTATE 원시코드(`P2013`/`P2014`/`P2015` 등) + 매핑된 `code`.

## 성공 이벤트 ("오류 없음"과 "실제 사용됨" 구분)
`approval_succeeded`(+`self_approval`), `approval_rejected`, `approval_revoked`, `export_prepared`(+`blocks`), `image_regenerated`, `generation_completed`(+`blocks`·`claims`), `generation_failed`(+`stage`). 병원은 `hospital`(해시 8자).

## 잔여 워커 (`obs=reap_stale`)
`reaped`(회수 건수). 정상은 0 — 급증하면 워커 급사/heartbeat 문제.

## 용량 (`obs=storage_stats`) — 관리 명령
```bash
python -m store.storage_stats
```
전체/병원별 scene_images 용량·개수·평균/최대·최근7일·DB 대비 비중. R2/S3 이전 의사결정 지표(매 요청 아님, 정기 실행). `OWNER_URL` 사용.

## 로그에 절대 넣지 않는 것(GPT)
대본·claim 내용, 승인/반려 **사유 원문**, 병원 slug/이름, 사용자 이메일, 이미지 prompt 원문, 원시 UUID. → 식별자는 route 패턴·`<id>` 마스킹·일방향 해시(`hid`)·`request_id`로만.
