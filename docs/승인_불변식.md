# 승인·편집 무결성 불변식 (확정본)

GPT 검토로 확정한 승인/편집 정책. service 계층은 이 규칙을 유일한 근거로 삼는다.
라우트(대시보드·/studio)는 이 규칙을 재구현하지 않고 service를 호출한다.

## 승인 상태 모델 (`version_approval_states.status`)

| 상태 | 의미 |
|------|------|
| `none` | 새 버전 기본값(미검토) |
| `pending` | 검토 대기(선택적) |
| `approved` | 해당 version 승인됨 |
| `rejected` | 검토 결과 반려 |
| `revoked` | 승인 후 문제 발견으로 승인 철회 |
| `superseded` | 새 current version이 생겨 최종 사용 대상에서 제외(과거 승인 이력은 유효) |

## 불변식 15

1. 승인은 `hospital_id + script_id + version_id`에 귀속된다. *(구현: version_approval_states)*
2. 승인 대상 version은 승인 시점의 `scripts.current_version_id`여야 한다. **[approval service에서 추가]**
3. 승인된 version 및 승인 근거 데이터는 직접 수정하지 않는다. *(구현: fn_reject_if_version_approved 트리거가 승인된 version의 blocks/sentences/claims/assessments INSERT 동결)*
4. 편집은 새 immutable version을 생성한다. *(구현: create_edited_version)*
5. 새 version은 승인을 승계하지 않는다(status='none'으로 시작). *(구현: create_edited_version)*
6. 편집 저장(새 version + 콘텐츠 + current 전환)은 단일 트랜잭션이다. *(구현: create_edited_version, CAS는 마지막)*
7. 편집은 `base_version_id`(expected_current)로 optimistic locking한다. *(구현: create_edited_version CAS)*
8. 편집과 승인은 동일 script/version을 기준으로 직렬화한다. *(구현: create_edited_version=script FOR UPDATE, approve=version advisory lock + content 동결 트리거가 동일 lock 공유)*
9. 승인 전 필수 claim/evidence 검수 조건을 재검사한다. *(구현: fn_approve_version — is_claim claim이 모두 verified & support_level∉{unverified,unsupported}가 아니면 23514)*
10. 승인·반려·철회는 actor 권한을 DB membership 기준으로 검증한다. *(구현: fn_approve_version active approver/admin 역할 검사)*
11. 작성자와 승인자는 원칙적으로 달라야 한다. **[approval service에서 추가 — script_versions.created_by 필요]**
12. 자기승인은 명시적 override 권한·사유·별도 audit가 있을 때만 허용한다. **[추가 — hospitals.allow_self_approval + 사유 + audit action 'approval.self_approve']**
13. 승인 후 evidence/claim 상태 변경은 차단하거나 먼저 승인을 철회해야 한다. *(구현: fn_reject_if_version_approved가 claims·claim_assessments INSERT 동결)*
14. 최종 publish/export는 current이며 approved인 version만 허용한다. **[추가 — export gate + 선택적 published_version_id]**
15. 모든 상태 전이는 append-only audit event로 기록한다. *(구현: fn_approve_version audit_events; reject/revoke도 동일 패턴 추가)*

## 승인 전제조건 (fn_approve_version 재검사)

- target version == current version *(inv 2)*
- version 상태가 `none`/`pending` *(approved 재승인 방지)*
- unresolved/rejected blocking claim = 0 *(inv 9)*
- 승인자 = 유효 membership + approver/admin role *(inv 10)*
- 작성자 ≠ 승인자 (또는 자기승인 override) *(inv 11/12)*

## 예외 타입 (services/exceptions.py) → HTTP

| 예외 | HTTP | 의미 |
|------|------|------|
| `Unauthorized` | 401 | 세션 없음 |
| `NotFound` | 404 | 병원/스크립트/버전 없음 |
| `Forbidden` | 403 | 권한 없음(역할·테넌트) |
| `VersionConflict` | 409 | base_version 불일치(다른 편집 선반영) |
| `InvalidStateTransition` | 409 | 허용되지 않는 상태 전이 |
| `ApprovalPrerequisiteFailed` | 422 | 미검증 claim 등 전제조건 미충족 |
| `SelfApprovalNotAllowed` | 403 | 자기승인 조건 미충족 |
| `SnapshotIntegrityError` | 409 | 복원 자료 무결성 불일치 |
| `HospitalBusy` | 409 | 병원당 active job 1개 위반 |

## 실행 계약 (P2-1 확정)

```
create_job(pending) → snapshot_job_materials(FOR UPDATE + 봉인)
→ claim_job(CAS + worker_token) → materialize_job_snapshot(size/SHA-256 검증) → pipeline
```

## 승인 상태 전이표 (approval service에서 강제)

| 현재 | 동작 | 결과 | 조건 |
|------|------|------|------|
| none/pending | approve | approved | current version + 전제조건 + 역할 |
| none/pending | reject | rejected | 역할 + 사유 |
| rejected | resubmit | pending | — |
| approved | revoke | revoked | 사유 필수 + admin |
| revoked | (재검토) | 새 version 요구 | — |
| approved | reject | **금지** | — |
| rejected | revoke | **금지** | — |

`superseded`는 상태가 아니라 `version_approval_states.superseded_by_version_id`로 표현(승인 이력 status는 보존).

## 작성자 정의 (자기승인 판정 기준)

- `source='editor'` version → 작성자 = `created_by_membership_id`(그 편집을 한 membership).
- `source='ai'` version → `generation_job_id`로 job 연결, 작성자 = 생성 **요청자**(job.created_by_membership_id). 자기승인 판정에서 AI 최초 생성 version의 작성자는 생성 요청자로 본다(병원 정책).
- `source='migration'` → 작성자 없음(NULL, system).

## 자기승인 capability

자기승인은 다음을 **모두** 만족할 때만:
- `hospitals.allow_self_approval = true`
- actor가 **admin** role 보유(= `approval.self_override` capability. 일반 approver와 분리)
- 사유(trimmed non-empty, 길이 제한)
- target version 작성자 == actor.membership_id
- audit action = `approval.self_approve` + 당시 정책값(allow_self_approval) snapshot 기록

## 범위 문구

> P2-1 데이터 무결성 완료. 현재 운영 정책은 병원당 active generation job 1개이며,
> 동일 병원 병렬 실행 또는 stale lease 자동 회수 도입 전 job별 작업 디렉터리 격리를 선행한다.
