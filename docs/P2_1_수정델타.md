P2 기준 델타. 6개 모순·보안구멍 + 문서 정정만. 전면 재설계 아님.

## 1. approvals append-only 모순 → **version_approval_states(mutable) + audit_events(history)** 로 확정

문제: append-only라면서 `revoked_at IS NULL` 부분 유니크를 쓰면, revoke 이벤트를 추가해도 기존 approved 행의 `revoked_at`은 NULL이라 활성 승인이 남고 재승인이 막힘 → 모순.

**확정(두 모델 혼합 제거)**:
- `approvals` 테이블(및 `revoked_at` 부분 유니크) **폐기**.
- **현재 상태(mutable, 버전당 1행)**:
```
version_approval_states
- id uuid PK, hospital_id, version_id
- status text NOT NULL CHECK(none|approved|rejected) DEFAULT 'none'
- approver_membership_id uuid NULL
- assessment_set_hash text NULL, version_content_hash text NULL, compliance_policy_version text NULL
- decided_at timestamptz NULL, updated_at timestamptz NOT NULL DEFAULT now()
FK (hospital_id, version_id) -> script_versions(hospital_id, id)
FK (hospital_id, approver_membership_id) -> hospital_memberships(hospital_id, id)
UNIQUE (hospital_id, version_id)      -- 버전당 상태 정확히 1행
UNIQUE (hospital_id, id)
```
- **이력(append-only)** = `audit_events`에 `approval.approve|revoke|reject` 기록(actor·전후 status·해시·사유).
- 규칙: 새 버전 생성 시 상태행 없음(=`none`) → 승인/취소/반려는 **이 1행을 UPDATE**(부분 유니크 불필요). 재승인 정상 동작. "무엇을 승인했나"는 audit_events + 상태행의 해시 3종으로 재현.

## 2. review token ↔ RLS 부트스트랩 → **`exchange_review_token()` SECURITY DEFINER**

문제: 외부 요청은 token만 알고 hospital_id를 모름. RLS 아래선 review_links를 읽어야 hospital_id를 아는데, 읽으려면 hospital_id가 필요 → 순환.

**확정**:
- runtime role(`app_rw`)에 **`review_links` 직접 SELECT 권한 미부여**.
- 전용 함수:
```sql
CREATE FUNCTION exchange_review_token(p_token_digest bytea)
RETURNS TABLE(hospital_id uuid, version_id uuid, link_id uuid, permission text)
LANGUAGE sql
SECURITY DEFINER
SET search_path = pg_catalog, public   -- 고정 search_path(하이재킹 방지)
AS $$
  SELECT hospital_id, version_id, id, permission
  FROM review_links
  WHERE token_hash = p_token_digest
    AND revoked_at IS NULL
    AND expires_at > now()
$$;
-- app_rw에는 EXECUTE만, review_links 테이블 권한은 없음
REVOKE ALL ON FUNCTION exchange_review_token(bytea) FROM PUBLIC;
GRANT EXECUTE ON FUNCTION exchange_review_token(bytea) TO app_rw;
```
- 흐름: 외부 `GET /r/<token>` → 앱이 HMAC digest 계산 → `exchange_review_token(digest)` 호출 → **최소 정보만** 반환 → 성공 시 **HttpOnly·Secure·SameSite=Strict 리뷰 세션 쿠키** 발급 → `/r/<link_id>`(clean URL)로 **redirect**(토큰 URL 제거) → 이후 요청은 쿠키에서 hospital_id 도출해 `set_config('app.hospital_id', …, true)` 적용 후 RLS 하에서 조회.
- 함수는 digest·expiry·revoked만 확인하고 대본 본문은 반환 안 함(본문은 세션 확립 후 RLS 경로로).

## 3. `claim_latest_assessment` view RLS 우회 방지

문제: view 소유자가 BYPASSRLS(`app_owner`)면 view가 tenant RLS를 우회.

**확정(PG15+)**:
```sql
CREATE VIEW claim_latest_assessment
WITH (security_invoker = true) AS      -- 호출자 권한/RLS로 실행
SELECT DISTINCT ON (hospital_id, claim_id) *
FROM claim_assessments
ORDER BY hospital_id, claim_id, created_at DESC, id DESC;
```
- PG<15 대비: view를 **BYPASSRLS 아닌 role**이 소유하도록 구성.
- 결정성: `DISTINCT ON (hospital_id, claim_id)` + `ORDER BY hospital_id, claim_id, created_at DESC, id DESC`(동시각 tie는 id로).
- 인덱스: `claim_assessments (hospital_id, claim_id, created_at DESC, id DESC)`.

## 4. migration_imports crash/concurrency → **포인터를 같은 트랜잭션에 커밋 + lease**

문제: script/version COMMIT 후 migration_imports 갱신 전 크래시 → 고아 데이터 + hash-skip로 영구 잔존.

**확정**:
- script/version/block/sentence/claim 삽입과 `migration_imports(script_id, version_id, status='imported')` 갱신을 **동일 트랜잭션에서 커밋**. (구조 커밋과 포인터가 원자적)
- 필드 추가: `attempt_count int NOT NULL DEFAULT 0`, `lease_expires_at timestamptz NULL`, `last_heartbeat_at timestamptz NULL`, `last_error_at timestamptz NULL`.
- 재실행 규칙:
  - `validated` → 전체 skip
  - `imported` → 구조 import skip, **evidence만 재시도**
  - `pending` + `lease_expires_at < now()` → 다른 워커가 인계(lease 획득)
  - `failed` → 명시적 retry(attempt_count++)
  - `script_id/version_id`가 이미 있으면 → **중복 script 생성 금지**(기존 재사용)
- 워커는 처리 중 `last_heartbeat_at` 갱신, lease로 동시 처리 방지.

## 5. OTP approver → **첫 구현은 로그인 approver membership 전용**

- 최종 승인은 **로그인한 approver membership만**. `version_approval_states.approver_membership_id`(NOT NULL when approved).
- bearer review link만으로는 **승인 불가**(익명=comment_only).
- OTP가 실제 필요해지는 단계에서 확장(그때 추가):
```
external_approvers(id, verified_email, challenge_id, verified_at, ...)
version_approval_states.external_approver_id  (membership 대체 경로)
CHECK: approver_membership_id 또는 external_approver_id 중 정확히 하나
```
- 지금은 external 경로 미구현(스키마도 후속).

## 6. global/user RLS 정책 분리

**style_rules — 작업별 정책 분리**:
```sql
ALTER TABLE style_rules ENABLE ROW LEVEL SECURITY; ALTER TABLE style_rules FORCE ROW LEVEL SECURITY;
-- SELECT: global + 현재 병원
CREATE POLICY sr_sel ON style_rules FOR SELECT TO app_rw
  USING (scope='global' OR hospital_id = current_setting('app.hospital_id', true)::uuid);
-- INSERT/UPDATE/DELETE: 현재 병원 규칙만 (global 금지)
CREATE POLICY sr_ins ON style_rules FOR INSERT TO app_rw
  WITH CHECK (scope<>'global' AND hospital_id = current_setting('app.hospital_id', true)::uuid);
CREATE POLICY sr_upd ON style_rules FOR UPDATE TO app_rw
  USING (scope<>'global' AND hospital_id = current_setting('app.hospital_id', true)::uuid)
  WITH CHECK (scope<>'global' AND hospital_id = current_setting('app.hospital_id', true)::uuid);
CREATE POLICY sr_del ON style_rules FOR DELETE TO app_rw
  USING (scope<>'global' AND hospital_id = current_setting('app.hospital_id', true)::uuid);
-- global 생성·승격·수정은 platform admin(app_owner/전용 role) 전용
```
**users — 자유 조회 금지**:
- `app_rw`에 `users` 전체 SELECT 미부여. 접근은 셋 중 하나:
  - (택1·권장) **전용 auth role/repository**만 users 인증 조회, 앱 일반경로는 membership 통해 필요한 이름만.
  - 또는 제한 view `user_directory`(self/같은 병원 멤버만) + RLS.
- 화면 표기용 이름은 `hospital_memberships` 조인으로 해당 병원 멤버 한정 노출(전역 users PII 비노출).

## 문서 정정

- **신규 테이블 수정**: `version_approval_states` 추가로 신규 테이블 = **10개**(membership_roles, script_sentences, claim_assessments, source_versions, style_rule_sources, migration_imports, audit_events, notification_outbox, rate_limit_buckets, **version_approval_states**) + view 1개(`claim_latest_assessment`). (기존 `approvals` 폐기.) — "8개" 표기 오류 정정.
- **FK 표현 구분**: SQLAlchemy 모델은 `ForeignKey(..., use_alter=True, name=...)`로 선언하되, **Alembic 마이그레이션은 테이블 생성 후 `op.create_foreign_key()`**로 순환 FK를 명시적 alter 단계로 표현(모델 선언과 마이그레이션 표현을 구분).
- **tenant 설정 = 파라미터화**: 문자열 보간 `SET LOCAL` 금지 → `SELECT set_config('app.hospital_id', :hospital_id, true)`(바인드 파라미터, 인젝션 차단).
- **런타임 쿼리 규약**: 모든 runtime 쿼리는 **tenant context가 설정된 트랜잭션 내부**에서만 실행(베이스 리포지토리가 `set_config` 미설정 시 실패 처리).
- **rate_limit_buckets 명세**:
```
rate_limit_buckets
- bucket_key_hash bytea NOT NULL       -- (scope+identity) HMAC
- window_started_at timestamptz NOT NULL
- request_count int NOT NULL DEFAULT 0
- expires_at timestamptz NOT NULL
PRIMARY KEY (bucket_key_hash, window_started_at)
-- 원자적 증가: INSERT ... ON CONFLICT (bucket_key_hash, window_started_at) DO UPDATE SET request_count = request_count+1
INDEX (expires_at)   -- 만료 정리(cleanup) 배치용
```

## 남은 기본값 3개 — **승인 확정 반영**
1. 리뷰 토큰: HMAC-SHA256 digest + 세션쿠키 교환 + clean URL + `Referrer-Policy:no-referrer`/`Cache-Control:no-store` + CSRF.
2. 댓글: raw 저장, **출력 시 문맥별 escape 1회**(double-encode 회피).
3. rate limit: 현재 PostgreSQL bucket, 다중 인스턴스 확장 시 Redis.

## 확정 상태
승인 모델(version_approval_states+audit), RLS bootstrap(exchange_review_token SECURITY DEFINER), view RLS(security_invoker), migration crash 복구(동일TX 포인터+lease+재실행규칙) — 4개 모두 명확화. OTP는 membership 전용으로 축소, style_rules/users RLS 정책 분리 완료.
