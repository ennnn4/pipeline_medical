## P0 반영 대응

### 1. topic → script_id(UUID) 식별  ✅
- `ingest_content(engine, hospital_id, job_id, topic, script_list, target_script_id=None)`:
  - `target_script_id is None` → **새 대본** 생성, 있으면 **그 대본의 새 immutable 버전**.
  - `topic`은 표시용. 실제 식별자는 script UUID.
- 대시보드는 `_pg_script_id_for_topic()`로 기존 대본을 찾아 script_id를 넘김(topic은 조회 편의, identity는 UUID).
- 검증(sim): 같은 script_id로 재생성 → 같은 대본의 **버전 2개**(새 대본 아님).
- ⚠️ 남음: 대시보드 병원 slug↔PG hospital 이름 매핑은 아직 이름 일치 전제(멀티병원 전 UUID 명시 저장 필요) — P1로 관리.

### 2. request_idempotency_key vs content_hash 분리  ✅
- `generation_jobs.request_idempotency_key`(브라우저 `crypto.randomUUID`, `UNIQUE(hospital_id, request_idempotency_key)`): 더블클릭·재전송 방지. run 폼 `onsubmit`에서 생성 + 버튼 disable.
- `generation_jobs.content_hash`(생성 결과 canonical SHA-256): 동일 결과 재적재 방지·감사.
- 정책: 같은 요청 재시도→기존 job 반환. 명시적 재생성(새 요청키)→새 버전. 동일 content 재적재→기존 버전 reused.
- 검증(sim): 동일 reqkey→reused, 동일 content 재적재→reused.

### 3. generation_job을 run.py 전에 생성 + 실패 보존  ✅
- 흐름: `create_job(pending)`(TX1 commit) → `mark_job(generating, started)` → run.py → `generated` → `ingesting` → `ingest_content`(completed) → **예외 시 별도 TX로 `failed`**(error_code/message, finished_at).
- 상태: pending/generating/generated/ingesting/completed/failed/cancelled/stale. `phase`·`started_at`·`heartbeat_at`·`finished_at`·`error_code`·`retry_count`.
- `reap_stale()`: heartbeat 멈춘 generating/ingesting → stale(서버 급사 대비).
- outbox는 도입 안 함(현재 규모 불필요, GPT 의견 반영).

### 4. 세션/쿠키 보안 + users.yaml 폴백 차단  ✅
- 두 앱 `SESSION_COOKIE_HTTPONLY=True`, `SAMESITE='Lax'`, `SECURE=배포시 True`.
- 로그인 시 `session.clear()`(세션 고정 방지).
- 스튜디오 `tenant()`는 **세션의 role/hospital 안 신뢰**, membership을 매 요청 PG 재조회(원래 그러함).
- `DISABLE_YAML_FALLBACK=1`로 users.yaml 폴백 즉시 차단 가능(PG 이전 후 제거 예정).

### 5. Alembic 드리프트 정리  ✅
- `0001` 불변. `0002_scene_images`·`0003_generation_jobs` **adoption revision** 추가: `CREATE TABLE IF NOT EXISTS`+컬럼 `ADD IF NOT EXISTS`+RLS/정책/grant 재적용(기존 운영 DB/신규 DB 모두 안전).
- 런타임 `CREATE TABLE IF NOT EXISTS`(seed_images/ingest)는 **마이그레이션 검증 후 제거 대상**으로 유지(현재 수동 채택 경로와 공유).
- ⚠️ 남음: 운영 복제본에서 `alembic upgrade head → downgrade -1 → upgrade head` 검증 후 런타임 DDL 제거(P1).
